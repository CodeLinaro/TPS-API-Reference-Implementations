# tree-sitter-edn

A tree-sitter grammar for EDN (CBOR Extended Diagnostic Notation, RFC 8610
Appendix G), used to drive editor syntax highlighting (Neovim, Zed).

## Embedded/no_std exemption

This crate is exempt from the workspace's default no_std/embedded/
cross-compilation requirement (see root `CLAUDE.md`). It wraps a generated C
parser via the `tree-sitter`/`tree-sitter-language` crates and only makes
sense as dev tooling feeding an editor or the `tps_ts_highlight_tool` preview
CLI on a developer's machine — there is no embedded consumer. `std` is
allowed and no cross-compilation target guarantees are made.

## Layout

- `grammar.js` — the grammar source (tree-sitter DSL). Highlighting fidelity
  is favored over strict validation; `tps_minicbor::edn`'s hand-written
  parser remains the source of truth for EDN correctness.
- `src/parser.c`, `src/node-types.json`, `src/grammar.json` — generated by
  `tree-sitter generate --js-runtime native --abi 15` (Node.js is not
  required; the CLI's built-in QuickJS runtime evaluates `grammar.js`).
  Committed, per standard tree-sitter grammar-crate practice.
- `bindings/rust/` — the Rust binding (`LANGUAGE` const), mirroring the shape
  of `tree-sitter-json`/`tree-sitter-rust` on crates.io.
- `queries/highlights.scm` — the syntax highlighting query, consumed both by
  `tps_ts_highlight_tool` and directly by Neovim/Zed.
- `test/corpus/*.txt` — `tree-sitter test` corpus; the primary correctness
  gate for this crate.
- `examples/*.edn` — snippets adapted from `tps_minicbor/tests/edn.rs` and
  RFC 8610 Appendix G/H, used by the `tests/fixtures.rs` smoke test.
- `editors/` — drop-in Neovim/Zed configuration artifacts.

## Grammar notes

CDDL and EDN use different comment syntax — EDN comments are delimited by a
pair of `/` (RFC 8610 Appendix G.6), unlike CDDL's `;` line comments — so this
is a separate grammar from `tree-sitter-cddl` rather than a shared one.

EDN is a single top-level data item (not a sequence of items), matching
`tps_minicbor::edn::parse_edn`; `source_file` is `optional($.value)`.

## Regenerating the parser

After editing `grammar.js`:

```
tree-sitter generate --js-runtime native --abi 15
tree-sitter test
```

## Regenerating the WASM binding

`tree-sitter-edn.wasm` (committed alongside `src/parser.c`) is consumed by
`tps_cbor_gui`'s browser-side Monaco syntax highlighting via
`web-tree-sitter`. Requires `emcc` (Emscripten) on `PATH`; `tree-sitter build
--wasm` downloads the matching wasi-sdk automatically on first run. Re-run
after any `grammar.js`/parser regeneration:

```
tree-sitter build --wasm
```
